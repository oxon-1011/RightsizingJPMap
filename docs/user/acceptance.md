# 取り込めるデータの条件

RightsizingJPMap の地図には、施設の一覧、市区町村別の統計、管轄範囲などの手持ちのデータ（以下、**自前データ**）を重ねられる。
この文書は、取り込めるファイルの条件と、条件を満たさないときの直し方をまとめる。

条件を1つでも満たさない行や地物があると、アプリはファイル全体を取り込まない。
そのとき画面には、満たさなかった条件と、その行や地物の番号を先頭から5件まで示す。
アプリは値を推測で直さない（先頭の 0 が落ちた団体コードに 0 を補う、緯度と経度を入れ替える、など）。
推測で直すと、誤った値がそのまま地図に載るおそれがあるからである。
直し方は、この文書の「拒否される例と直し方」に示す。

## 取り込める形式

| 形式 | 拡張子 | 主な用途 |
|---|---|---|
| CSV | `.csv` | 施設の一覧（緯度と経度つき）、市区町村別やメッシュ別の統計 |
| Parquet | `.parquet` | 上と同じ内容を、型つきの列で持つファイル |
| GeoJSON | `.geojson`、`.json` | 施設の点、道路などの線、管轄範囲などの面 |

形式はファイルの拡張子で決める（大文字と小文字は区別しない）。
拡張子は読み方を選ぶためだけに使い、中身は形式ごとの条件で全件を検査する。
そのため、拡張子が `.geojson` でも、中身が GeoJSON の条件を満たさなければ取り込まない。

Excel（`.xlsx`）、Shapefile、GeoPackage、KML は取り込めない。
Excel の表は CSV に、Shapefile などの地理空間ファイルは GeoJSON に変換してから取り込む（「ほかの形式からの変換」の節）。

ファイルの大きさは 100MB を目安とし、超えると警告を出す予定である。
この値は、画面を作るときに調整する。

## CSV と Parquet の条件

- **文字コード**：UTF-8 にする。BOM 付きの UTF-8 も読める。Shift_JIS は読めない。
- **区切りと見出し**：区切りはカンマにし、1行目にすべての列の名前を書く。名前が空の列は置かない。同じ列名を2つ以上の列に付けない。
- **データの行**：列名の行のほかに、データの行を1行以上持つ。
- **結合用の列**：次の表のどれか1組だけを、この列名で持つ。列名は大文字と小文字を区別するので、半角の小文字で書く（`Code` や `LAT` は結合用の列とみなさない）。1組もないファイルと、2組以上あるファイルは取り込まない。`lat` と `lon` は両方そろえる。片方だけのファイルも取り込まない。
- **属性の列**：結合用の列のほかに、列をいくつ持ってもよい。数値の列は、結合したあとにメッシュや市区町村ごとに合計できる。

| 列名 | 重ねる先 | 値の条件 |
|---|---|---|
| `code` | 市区町村 | 5桁の団体コード。地図で塗る単位のコードに限る（下の箇条書き） |
| `mesh` | 1km メッシュ | 8桁の数字（3次メッシュコード） |
| `lat` と `lon` | 点として重ね、メッシュと市区町村の両方に集計する | 十進数の緯度と経度（世界測地系）。北緯 20〜46 度、東経 122〜154 度に入る |

`code` に書ける団体コードは、地図で塗る単位のものだけである。

- 政令指定都市は区のコード（札幌市中央区の `01101` など）を使う。市そのもののコード（札幌市の `01100`）は取り込まない。
- 東京都は特別区のコード（千代田区の `13101` など）を使う。
- 都道府県のコード（`13000` など、末尾が `000`）は取り込まない。
- 福島県の浜通り地域の 13 市町村は、1つの地域 `07999` として扱う。いわき市（`07204`）のような個別のコードは取り込まない（理由は [data-sources.md](data-sources.md) の「浜通り地域」）。
- 浜松市は、2024 年 1 月 1 日の再編後の3区（`22138`〜`22140`）を使う。再編前の7区のコード（`22131`〜`22137`）は取り込まない。

結合用の列の値が空の行も、条件を満たさない行として数える。

`mesh` の値は、3次メッシュコードとしての形だけを検査する。
8桁の数字で、5桁めと6桁め（2次メッシュの番号）が 0〜7 のものに限る。
アプリのベースデータ（2020 年に人が住んでいたメッシュ）にないメッシュも取り込めるが、人口あたりの値は計算できないので表示しない。

`lat` と `lon` は、度を単位とする十進数で書く（`35.681236` など）。
指数の表記（`3.5e1`）、前後の空白、`+` の符号は使えない。
度分秒（`35°40'52"`）は取り込まない。
旧日本測地系の座標は範囲の検査では見分けられないので、取り込めても位置が数百メートルずれる。
世界測地系（JGD2011 か WGS84）に変換してから取り込む。

Parquet のファイルには、次の条件も加わる。

- `code` 列は文字列型にする。整数型の `code` 列を持つファイルは取り込まない。北海道から栃木県まで（`01`〜`09`）のコードは、整数にした時点で先頭の 0 が落ちるからである。
- `mesh` 列は、8桁の整数型でも文字列型でもよい。
- `lat` と `lon` の列は、数値型（整数か浮動小数点数）でも文字列型でもよい。文字列型なら、CSV と同じ十進数の表記にする。
- 結合用の列が、これら以外の型（日付型など）のファイルは取り込まない。

## GeoJSON の条件

- **全体の形**：RFC 7946 の FeatureCollection にし、地物（`features` の要素）を1つ以上持つ。文字コードは、RFC 7946 の定めどおり UTF-8 にする。
- **地物の形**：各地物は `type` が `Feature` で、`properties` はオブジェクトか `null` にする。
- **座標の順と測地系**：座標は経度、緯度の順に、世界測地系（WGS84）の度で書く。3つめの値（高さ）はあってもよい。`crs` メンバーは書かないのが RFC 7946 の既定である。書く場合は、`{"type": "name", "properties": {"name": "urn:ogc:def:crs:OGC:1.3:CRS84"}}` の形（`urn:ogc:def:crs:OGC::CRS84` も可）のときだけ取り込む。`crs` が `null` のファイルと、`EPSG:4326` などほかの書き方のファイルは取り込まない。
- **座標の範囲**：すべての座標が、北緯 20〜46 度、東経 122〜154 度に入る。
- **ジオメトリの種類**：1つのファイルの地物は、次の3種類のどれか1つにそろえる。ジオメトリが `null` の地物は持たない。
- **ジオメトリの形**：線は2つ以上の位置を持つ。面の輪（外周と穴）は4つ以上の位置を持ち、最初と最後の位置を同じにして閉じる。
- **属性**：各地物の `properties` を属性として扱う。数値の属性は、結合したあとに合計できる。

| 種類 | ジオメトリ | 地図での扱い |
|---|---|---|
| 点 | `Point` | 点として重ね、メッシュと市区町村の両方に集計する |
| 線 | `LineString`、`MultiLineString` | 重ねて表示するだけ |
| 面 | `Polygon`、`MultiPolygon` | 重ねて表示するだけ。面の内側の人口は集計しない |

この表にない種類（`MultiPoint`、`GeometryCollection`）は取り込まない。

## 行と地物の番号の数え方

取り込めなかったときに示す番号は、次のように数える。

- **CSV**：列名の行を1行目とした行番号。表計算ソフトで開いたときの行番号と同じになる。ただし、値の中に改行を含む行や空の行があると、それより後ろの行番号はずれる。
- **Parquet**：先頭の行を1とした番号。
- **GeoJSON**：`features` の配列の先頭の地物を1とした番号。

## 拒否される例と直し方

### Shift_JIS で保存した CSV

Excel で「CSV（コンマ区切り）」を選んで保存すると、Windows の既定では Shift_JIS になることが多い。
このファイルは文字コードの段階で読み込めない。

Excel で開き直し、「名前を付けて保存」で「CSV UTF-8（コンマ区切り）」を選んで保存し直す。
コマンドで直す場合は、macOS や Linux の `iconv` を使う。

```bash
iconv -f CP932 -t UTF-8 input.csv > output.csv
```

`iconv` のこの使い方は、macOS 27.2 の `iconv` で、Shift_JIS（CP932）に変換したファイルが元の UTF-8 のファイルに戻ることを確かめた（2026-11-07）。
Excel の保存の手順は、この文書を書いた環境では確かめていない。

### 先頭の 0 が落ちた団体コード

北海道の `01101` が `1101` になっている、という形である。
CSV を Excel で開いて保存し直すと、団体コードが数値とみなされて先頭の 0 が落ちることがある。

元のデータから団体コードを文字列のまま書き出し直す。
Excel で作業する場合は、CSV を開くときに `code` の列のデータの形式を「文字列」にして読み込む。
すでに 0 が落ちた列は、`=TEXT(A2,"00000")` のような式で5桁の文字列に直してから、値として貼り付ける。
Excel の操作は、この文書を書いた環境では確かめていない。

### 6桁の団体コード

総務省の全国地方公共団体コードには、5桁のコードの後ろに検査数字を1桁付けた6桁の形がある（千代田区の `131016` など）。
アプリは5桁の形だけを取り込む。
6桁のコードの先頭5桁（`13101`）を残した列にしてから取り込む。

### 政令指定都市のコード

札幌市の `01100` のように、政令指定都市そのもののコード（末尾が `100`）は、地図で塗る単位にないので取り込まない。
区ごとの値があれば、区のコード（`01101`〜）の行に分ける。
市全体の値しかない場合、アプリは区に按分しない。
按分してよいかと、その方法は、データを用意する側で判断する。

### 緯度と経度の入れ違い

`lat` に `139.767125`、`lon` に `35.681236` が入っている、という形である。
緯度は北緯 46 度までの範囲を外れるので、取り込まない。
列名の `lat` と `lon` を入れ替えてから取り込む。

### 投影座標の GeoJSON

平面直角座標系などの投影座標のまま書き出した GeoJSON は、座標がメートル単位の大きな値（`-35000.5` など）になり、緯度と経度の範囲を外れるので取り込まない。
`crs` メンバーに `EPSG:6677` などが書かれている場合も取り込まない。
次の節の手順で、世界測地系の経度と緯度（EPSG:4326）に変換してから取り込む。

## ほかの形式からの変換

アプリは形式の変換をしないので、取り込む前に、利用者の手元のツールで GeoJSON に変換する。
以下の手順は一般的な例で、この文書を書いた環境（QGIS と GDAL を入れていない）では確かめていない。

### QGIS で変換する

1. Shapefile や GeoPackage を QGIS で開く。
2. レイヤーを右クリックし、「エクスポート」から「地物の保存」を選ぶ。
3. 形式に「GeoJSON」を、座標参照系に「EPSG:4326 - WGS 84」を選ぶ。
4. エンコーディングに「UTF-8」を選んで保存する。

### ogr2ogr で変換する

GDAL の `ogr2ogr` では、出力の座標参照系を `-t_srs` で指定し、`RFC7946=YES` で RFC 7946 に沿った GeoJSON を書き出す。

```bash
ogr2ogr -f GeoJSON -t_srs EPSG:4326 -lco RFC7946=YES output.geojson input.shp
```

属性の文字が Shift_JIS で書かれた Shapefile では、読み込むときの文字コードを指定する。

```bash
ogr2ogr -f GeoJSON -t_srs EPSG:4326 -lco RFC7946=YES -oo ENCODING=CP932 output.geojson input.shp
```

変換したファイルは、「GeoJSON の条件」を満たしているかを確かめてから取り込む。
とくに、1つのファイルのジオメトリの種類がそろっているかを確かめる。
点と面が混ざったデータは、種類ごとに別のファイルに分けて書き出す。

### Excel の表を CSV にする

Excel の「名前を付けて保存」で「CSV UTF-8（コンマ区切り）」を選ぶ。
保存する前に、結合用の列の名前を `code`、`mesh`、`lat`、`lon` のどれかに書き換えておく。
